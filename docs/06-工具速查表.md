# 06 · 诊断工具速查表（jcmd 优先 + Arthas · 含 macOS/Linux 对照）

> 生产以 **Linux** 为主；🍎 列为本机 macOS 演练时的等价命令。
> `<pid>` 获取：`jps -l | grep troubleshoot`（跨平台一致）。
> **JDK 9+ 一律 jcmd 优先**（一个 attach 覆盖一切，`jcmd <pid> help` 自发现）；
> jstack/jmap 仅用于 JDK 8 老服务器（演进映射见 01 手册 §3.2）。

## 一、JVM 诊断（JDK 9+/21 正统命令；🍎 macOS 差异标注）

| 用途 | 正统命令 | 🍎 macOS 差异 / JDK 8 兼容 |
|---|---|---|
| 找进程 | `jps -l` | 一致 |
| **命令自发现** | `jcmd <pid> help` | 一致 |
| 进程 CPU/内存总览 | `top -p <pid>` | `top -pid <pid>`（参数名不同） |
| **线程级 CPU 排名** | Linux: `top -Hp <pid>`；或两次 `jcmd <pid> Thread.print` 差分 `cpu=` | 🍎 无线程级 top → `jcmd <pid> Thread.print \| sed -E 's/^"([^"]+)".*cpu=([0-9.]+)ms.*/\2 \1/' \| sort -rn \| head`；或 Arthas `thread -n 3` |
| 线程号转16进制 | Linux: `printf '%x\n' <TID>` | 不需要：macOS nid 是线程名后 `[十进制]`，直接 `grep '\[<TID>\]'` |
| **抓线程栈/死锁** | `jcmd <pid> Thread.print`（死锁段: `\| grep -A 10 deadlock`） | 一致；JDK8: `jstack <pid>` |
| 线程状态统计 | `jcmd <pid> Thread.print \| grep 'java.lang.Thread.State' \| sort \| uniq -c` | 一致 |
| 浏览器看线程栈 | `curl .../actuator/threaddump` | 一致 |
| **堆快照（分区/Metaspace）** | `jcmd <pid> GC.heap_info` | JDK8: `jmap -heap`（JDK9+ 已不可用） |
| **GC 趋势(核心)** | `jstat -gcutil <pid> 1000 10`（jcmd 无流式采样，趋势仍用 jstat） | 一致 |
| GC 容量明细 | `jstat -gc <pid>` / `jstat -gcmetacapacity <pid>`（⚠️ 没有 `-gcmetaspace` 这个选项） | 一致 |
| **堆对象直方图(活体)** | `jcmd <pid> GC.class_histogram \| head -20` | 一致；JDK8: `jmap -histo` |
| 强制 Full GC | `jcmd <pid> GC.run`（对照实验用） | 一致 |
| 堆 dump（⭐重操作，STW） | `jcmd <pid> GC.heap_dump /tmp/heap.hprof` | 一致；OOM 自动 dump 靠 `-XX:+HeapDumpOnOutOfMemoryError`；JDK8: `jmap -dump:...` |
| **JFR 飞行记录(现代黑匣子)** | `jcmd <pid> JFR.start name=r settings=profile duration=120s filename=r.jfr` → `JFR.dump` | JMC 打开分析；间歇性故障追现场首选 |
| JVM 参数核对 | `jcmd <pid> VM.flags` | 一致 |
| **句柄统计** | `lsof -p <pid> \| wc -l`；按文件聚合 `lsof -p <pid> \| awk '{print $NF}' \| sort \| uniq -c \| sort -rn \| head` | 一致 |
| 句柄上限 | `ulimit -n` | 一致（调法不同：systemd unit vs launchd plist） |
| **连接统计** | `ss -antp \| grep <port>`（或 `netstat -antp`） | `netstat -an \| grep 8080`（无进程列，配 `lsof -i :8080`） |
| 线程明细列表 | `ps -T -p <pid>` | `ps -M -p <pid>`（无 CPU% 列） |
| 命令限时 | `timeout 30 <cmd>` | ❌无 timeout：`gtimeout`（brew coreutils）或后台 + `kill` |

## 二、Arthas（本地 4.0.4：`./scripts/arthas.sh`）

| 场景 | 命令 | 作用 |
|---|---|---|
| 启动 | `./scripts/arthas.sh` | 自动 attach 演练场进程（无进程列表，防误挂其他 Java 进程）；`<pid>` 显式指定 |
| 批处理 | `printf 'thread -n 3\nexit\n' > b.as && ./scripts/arthas.sh <pid> --batch-file b.as` | 非交互执行（⭐4.x 用 `--batch-file`，不是 `-c`） |
| 退出纪律 | 会话内 `exit` 只断开客户端；**彻底卸载 agent 用 `stop`**（重置增强类）。残留 agent 占用 3658 端口时，无参启动会自动 stop 释放 | 防止「端口被别的进程占着」attach 失败 |
| 总览 | `dashboard` | 线程/内存/GC 一屏 |
| **CPU 定位** | `thread -n 3` | 最耗 CPU 的 3 个线程+栈（= top + Thread.print 两步） |
| **死锁/阻塞源头** | `thread -b` | 直接指认持锁阻塞他人的线程 |
| 按状态筛线程 | `thread --state BLOCKED`（WAITING/TIMED_WAITING/RUNNABLE） | 成批挂起线程的现场 |
| 指定线程 | `thread <id>` | 看单个线程栈 |
| **慢接口追踪** | `trace com.lab.troubleshoot.web.OrderController '*' '#cost > 100'` | 方法级耗时树，只显示 >100ms 的调用链 |
| 观察入参/返回 | `watch 类 方法 '{params,returnObj}' -x 2 -n 3` | 不改代码的方法级日志 |
| 反编译 | `jad 类名` | 确认运行中的代码就是你以为的代码（热更排查） |
| **内存** | `memory`、`heapdump --live /tmp/h.hprof`、`vmtool --action getInstances --className java.util.ArrayList --limit 3` | 内存池/按需 dump/查运行时对象 |
| 类/方法信息 | `sc -d 类名`、`sm 类名` | 加载器、字段、方法签名 |
| **热修复** | `jad ... > B.java` → 改 → `mc B.java --d /out` → `retransform /out/....class` | 线上止血（重启失效，必须补版） |
| 退出 | `stop` | detach 并清理增强字节码 |

## 三、演练场管理与 MySQL 常用

| 用途 | 命令 |
|---|---|
| 连接 | `mysql -uroot -prootroot troubleboot_lab` |
| 执行计划 | `EXPLAIN SELECT ... ;`（关注 type/key/rows） |
| 慢查询开关 | `SET GLOBAL slow_query_log=1; SET GLOBAL long_query_time=0.5;` |
| 占连接者 | `SHOW PROCESSLIST;`（场景 16：SLEEP/长查询即占坑者） |
| 索引检查 | `SHOW INDEX FROM orders;` |
| 服务启停 | `./scripts/lab.sh` / `-restart` / `-stop` / `-status`；`-wait` 阻塞等灌数完成（脚本化/CI） |
| 环境体检 | `./scripts/lab.sh -doctor`（JDK/Maven/MySQL/端口/Arthas/磁盘 逐项 ✅❌） |
| GC 事件流 | `tail -f logs/gc.log`（-Xlog:gc 轮转 3×20M——jstat 是采样, GC 日志是每次停顿的第一手记录） |
| 堆外水位 | `jcmd <pid> VM.native_memory summary`（NMT 已开 summary）+ `/api/faults/oom-direct-memory/status` |
| 盲测出题 | `curl -X POST localhost:8080/api/faults/quiz`（只返回告警+分类, 不透露身份）/ `GET .../quiz/reveal` 揭晓 |
| 复盘模板 | `./scripts/diagnose.sh` 快照目录内自动生成 `REPORT.md`（预填证据+场景状态, 五节待填） |
| 清除演练库 | `./scripts/lab.sh -clean`（要求应用已停止; `-y` 跳过确认）；`-clean-all` 连演练产物一起清 |

## 四、本项目的「教具」接口一览

| 端点 | 用途 |
|---|---|
| `GET /api/faults` | 全部 16 场景状态 |
| `POST /api/faults/{id}/trigger[?参数]` / `stop` / `GET status` | 故障三连（参数见各场景手册） |
| `GET /api/metrics` | JVM 实时指标（控制台仪表同源） |
| `GET /api/health/ping` | 永快探针（分层判断第一锤） |
| `GET /api/order/{id}` | 正常毫秒级接口（场景16 受害者） |

| `GET /api/order/top-spenders?limit=500&mode=n+1\|batch` | 场景 13 对照（order_item 300万行） |
| `GET /api/payment/no-timeout` / `with-timeout` | 场景 14 对照 |
| `GET /api/inventory/deduct` | 场景 15 体验 |
| `GET /api/report/summary` | 场景 9 受害接口 |
| `GET /api/mock/downstream?delayMs=3000` | 模拟慢下游 |
| `GET /actuator/health\|metrics\|threaddump` | Spring 监控端点 |
